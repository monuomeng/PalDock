# P2-10 任务续做：开发计划

状态：**用户已批准（2026-11-24），代码完成**。负责人：Claude；分支 `claude/p2-external-channels`（P2 收尾前一起做，推送仍等 P2 全部完成）。背景与现状见 [P2 变更说明](../pr/p2-external-channels.md)。

## 前因

2026-11-24 实测：在飞书里给任务 #2dee25 发完第一句后，想接着同一个 worktree 再说一句，第二句被当成了新任务 #21d276，开了新 worktree，Codex 在新目录里找不到上一个任务的文件。

用户的要求（2026-11-24）：加「基于某个任务继续」；或者任务产出后不默认进「待验收」，而是等待新指令，由人明确下令才结束任务。

## 现状（改之前）

- 一个任务 = 一个子任务 = 一个 worktree（`<数据目录>/worktrees/<12 位编号>`，分支 `paldock/<12 位编号>`）+ 一个 Codex 会话（thread），之后每次 Run 共用这两样。
- AI 一轮做完后子任务进 `review`（界面叫「待验收」）。这时 AI 已经停下，任务并没有结束：
  - 「退回重做」= 带一句话在**同一个 worktree、同一个 Codex 会话**里再跑一轮。机制上它已经就是「继续」，只是名字和入口像「打回」。
  - 「验收通过」= 把改动提交到任务分支，任务结束（`succeeded` 是终态）。
- 外部单聊里，除命令外的每句话都当作**新任务目标**。所以第二句话不会回到上一个任务，这是这次问题的直接原因。

## 方案（已定）

任务做完一轮后停在「待命中」，单聊里接着说就是继续；结束必须由人明确下令。另外支持从已结束的任务分支接着开新任务。

### 1. 「待验收」改成「待命中」

- 状态不变（仍是 `review`），只改说法和按钮：「继续」（写下一步指令，同一 worktree、同一 Codex 会话再跑一轮）和「结束任务」（提交到任务分支，任务结束）。
- 继续必须写指令；提示词改为「用户的下一步指令：…」，并附原始目标。
- 审核记录仍用 `rework` / `accept` 两种（库里不改约束），界面上叫「继续」/「结束任务」。
- 桌面和手机两边说法一致。

### 2. 单聊的「当前任务」

每个单聊记一个当前任务（`external_conversations.current_task_id`，迁移 004；原来等「退回意见」的 `awaiting_token` 删掉，旧按钮作废）。在这个单聊确认新建的任务、用 `/continue` 选中的任务、点了「继续」的任务成为当前任务。任务结束（不管在手机还是电脑上结束、取消或失败）时，所有以它为当前任务的单聊都清掉，下一句话就是新任务；想接着已结束的任务做，用 `/continue` 选它。

单聊里一句普通的话（不是命令）按当前任务的状态处理，**继续不弹确认卡片**：

| 当前任务状态 | 处理 |
|---|---|
| 待命中 | 直接作为下一步指令继续，回「#xxxx 继续执行」 |
| 用 `/continue` 选中的已结束任务 | 基于它新建任务接着做（见第 4 节），新任务成为当前任务 |
| 执行中、等审批 | 不建任务，回「#xxxx 还在执行，这句话没有发出去」 |
| 阻塞 | 提示到电脑上恢复、重新开始或放弃 |
| 没有当前任务，或选中的任务已失败、已取消 | 和以前一样：当作新任务目标，先发确认卡片 |

任务进度发给来源会话，**也发给把它设为当前任务的单聊**（例如在手机上继续电脑上建的任务）。

群聊不变：普通的话仍是新任务目标（确认后建）；继续、结束、取消、审批只在单聊。

### 3. 命令

| 命令 | 作用 |
|---|---|
| `/new <目标>` | 不管当前任务，另起一个新任务（确认卡片） |
| `/continue` | 最近的任务列表（按最近活动排序）：编号、状态、多久之前、目标摘要；每个任务一个按钮，点了显示它做过什么（每一轮的指令、AI 的说明、改动，最近 5 轮），并设为当前任务 |
| `/continue <#编号或分支名> [指令]` | 设为当前任务；带指令时立即按第 2 节继续。认 `#2dee25`，也认 `paldock/75e3d4422a2b` |
| `/done [#编号]` | 结束当前任务（或指定任务）：发确认卡片，点「结束任务」才提交 |

`/tasks` 标出当前任务；`/status` 不带编号时看当前任务；`/help` 同步更新。

### 4. 基于已结束的任务继续

- 单聊里用 `/continue` 选中已结束的任务后说一句话、或桌面任务详情的「基于此任务继续」，会**新建一个任务**：worktree 从老任务分支的最新提交拉出（而不是项目 HEAD），提示词里带上老任务的目标和最后说明。
- 新任务记下来源（`tasks.continued_from_task_id`，迁移 004），任务详情显示「接续自」。新任务用新的 Codex 会话。
- 只能接续同一项目里已结束（`succeeded`）的任务；失败、取消的任务没有提交，请用现有的「重新开始」或另建任务。老分支被删了会明确报错。

### 5. 桌面

- 任务详情「待命中」：「下一步指令」输入框 +「继续」+「结束任务」。
- 已结束的任务：「基于此任务继续」，打开新建任务页，项目固定为来源项目。

## 测试

- 存储：最近任务按子任务最后变化排序、走索引 `subtasks_by_activity`；当前任务指针不改版本号、按任务找会话走 `conversations_by_current_task`；接续来源写入。
- P1 流程：继续不写指令被拒；未结束的任务不能接续；接续任务的 worktree 起点是老分支的提交，里面有老任务提交的改动。
- P2 端到端：待命中直接回复继续（同 worktree、同 thread，不弹确认）→ `/done` 结束 → 下一句是新任务；当前任务执行中时普通消息不建任务；`/continue` 列表 → 选中桌面上已结束的任务 → 一句话基于它的分支新建任务，进度发回单聊。

## 不做

- 一个任务里开多个 worktree、多个任务共用一个 worktree。
- 自动结束任务（比如多久没说话就结束）。
- 在 PalDock 里合并或推送分支（另列积压）。
