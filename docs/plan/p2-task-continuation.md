# P2-10 任务续做：开发计划

状态：**草案，待用户审阅**。负责人：Claude；分支 `claude/p2-external-channels`（P2 收尾前一起做，推送仍等 P2 全部完成）。背景与现状见 [P2 变更说明](../pr/p2-external-channels.md)。

## 前因

2026-11-24 实测：在飞书里给任务 #2dee25 发完第一句后，想接着同一个 worktree 再说一句，第二句被当成了新任务 #21d276，开了新 worktree，Codex 在新目录里找不到上一个任务的文件。

用户的要求（2026-11-24）：加「基于某个任务继续」；或者任务产出后不默认进「待验收」，而是等待新指令，由人明确下令才结束任务。

## 现状

- 一个任务 = 一个子任务 = 一个 worktree（`<数据目录>/worktrees/<12 位编号>`，分支 `paldock/<12 位编号>`）+ 一个 Codex 会话（thread），之后每次 Run 共用这两样。
- AI 一轮做完后子任务进 `review`（界面叫「待验收」）。这时 AI 已经停下，任务并没有结束：
  - 「退回重做」= 带一句话在**同一个 worktree、同一个 Codex 会话**里再跑一轮。机制上它已经就是「继续」，只是名字和入口像「打回」。
  - 「验收通过」= 把改动提交到任务分支，任务结束（`succeeded` 是终态）。
- 外部单聊里，除命令外的每句话都当作**新任务目标**。所以第二句话不会回到上一个任务，这是这次问题的直接原因。

## 方案

两种做法合在一起：**任务做完一轮后停在「等你下一步」，单聊里接着说就是继续；结束必须由人明确下令。** 另外支持从已结束的任务分支接着开新任务。

### 1. 「待验收」改成「等你下一步」

- 状态不变（仍是 `review`），只改说法和按钮：
  - 「退回重做」→「继续」：输入一句指令，在同一 worktree、同一 Codex 会话里再跑一轮。
  - 「验收通过」→「结束任务」：提交到任务分支，任务结束。
- 继续的提示词不再写「验收后要求修改」，改为「用户的下一步指令：…」，并附原始目标。
- 审核记录仍用 `rework` / `accept` 两种（库里不改约束，不加迁移），界面上叫「继续」/「结束」。

### 2. 单聊的「当前任务」

每个单聊记一个「当前任务」（`external_conversations.current_task_id`，迁移 004）。从这个单聊建的任务、或用 `/continue` 选中的任务，成为当前任务。

单聊里一句普通的话（不是命令）按当前任务的状态处理：

| 当前任务状态 | 处理 |
|---|---|
| 等你下一步（`review`） | **直接继续这个任务**，回一张「#xxxx 继续执行」卡片，卡片上写「想另起新任务请发 /new 内容」 |
| 执行中、等审批 | 不建新任务，回「#xxxx 还在执行，停下后再发；想另起新任务请发 /new 内容」 |
| 没有当前任务，或已结束、取消、失败 | 和现在一样：当作新任务目标，先发确认卡片 |

继续不再弹确认卡片：它不改项目、不开新 worktree，只是在同一个任务里多跑一轮，跑错了可以再继续或 `/cancel`。新建任务仍然每次确认。

群聊不变：群里不验收、不结束，也不做续做，普通的话仍然是新任务目标（确认后建）。

### 3. 新命令

| 命令 | 作用 |
|---|---|
| `/new <目标>` | 不管当前任务是什么，另起一个新任务（确认卡片） |
| `/continue <#编号或分支名> [指令]` | 把这个任务设为当前任务；带指令时立即继续。编号认 `#2dee25` 这种短号，也认 `paldock/75e3d4422a2b` 这种分支名 |
| `/done [#编号]` | 结束当前任务（或指定任务）：发确认卡片，点「结束任务」才提交 |

`/tasks` 和 `/status` 标出当前任务。`/help` 同步更新。

### 4. 基于已结束的任务继续

任务结束（`succeeded`）后分支上已经有提交，但这个任务不能再跑了。这时：

- 单聊 `/continue #编号 指令`，或桌面任务详情里的「基于此任务继续」按钮，会**新建一个任务**：worktree 从老任务分支的最新提交拉出（而不是从项目 HEAD），提示词里带上老任务的目标，说明「在上一个任务的结果上继续」。
- 新任务记下来源（`tasks.continued_from_task_id`，同一个迁移 004），任务详情里显示「接续自 #xxxx」。
- 新任务用新的 Codex 会话（老会话绑定在老 worktree 上）。
- 只支持从已结束（`succeeded`）的任务接续。失败、取消的任务没有提交，未提交的改动留在老 worktree 里；这两种请用现有的「重新开始」或在桌面上查看后另建任务。

### 5. 桌面

- 任务详情「等你下一步」时：一个输入框 +「继续」按钮，旁边「结束任务（提交到分支）」。
- 已结束的任务：「基于此任务继续」，打开新建任务页，项目和来源已填好。
- 任务列表状态文字同步改成「等你下一步」。

### 6. 通知卡片

一轮做完时单聊收到的卡片：标题「#xxxx 这一轮做完了，等你下一步」，正文是 AI 的说明，按钮只有「结束任务」；卡片底部写「直接回复就是继续这个任务；/new 另起新任务」。原来「退回重做」按钮和「请发退回意见」那一步去掉（直接回复就行）。

## 测试

- 状态与路由：单聊当前任务在 `review` 时普通消息续做（新 Run、同 worktree、同 thread）；执行中时不建任务并提示；无当前任务时走确认卡片；`/new` 总是新建；群聊不受影响。
- `/continue` 认短号和分支名，认不出或在群里使用时给出原因；`/done` 只在单聊，点确认后提交。
- 接续已结束任务：新 worktree 的起点是老分支的提交，老 worktree 不动；`continued_from_task_id` 写入并显示。
- 迁移 004：新列有默认值，老数据不受影响；查询仍走索引（`EXPLAIN QUERY PLAN` 固定）。
- P2 端到端测试补两条：「一轮做完 → 单聊再说一句 → 同一个任务继续 → /done 结束」；「已结束任务 → /continue → 新任务从老分支出发」。

## 不做

- 一个任务里开多个 worktree、多个任务共用一个 worktree。
- 自动结束任务（比如多久没说话就结束）。
- 在 PalDock 里合并或推送分支（另列积压）。

## 需要你决定的

1. **继续时要不要确认卡片**。建议不要（理由见第 2 节）；如果你希望每次都确认，改一个开关即可。
2. **按钮名**。建议「继续」/「结束任务」；如果你更习惯「验收通过」，可以只改通知文案、保留按钮名。
