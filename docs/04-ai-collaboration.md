# Codex 与 Claude 协作开发规范

## 协作方式

两者是平等开发者，由用户确定任务优先级。建议一个任务由一方负责实现，另一方独立审阅；审阅者不要同时修改同一工作目录。小任务不强制双人审阅；安全、数据迁移和供应商协议变更优先独立复核。任务最终由实际验证结果而非模型互相认同来判断。

当前本机未检测到可执行的 Claude 命令，本文件只是双方未来的共同协议；本轮没有调用 Claude，也没有替用户授权或安装。

## 任务划分与交接

每个任务记录：目标、范围、负责人、分支/worktree、输入与输出、依赖、验收标准、风险、状态。建议流程：

1. 阅读 README、根目录 AGENTS.md、CLAUDE.md 和关联文档；检查 Git 工作区与现有修改。
2. 为任务选择独立分支/worktree；确认无他人占用的相同文件范围。共享接口变更先形成 ADR 或明示契约。
3. 实现并运行适合该变更的检查；如有失败，记录原因和复现步骤。
4. 提交交接：变更目的、文件、验证命令及结果、风险、未完成事项、需要另一方判断的问题。
5. 审阅者独立检查变更和必要的测试，按严重程度反馈可复现问题；作者修复后重新核验。

## 可复制的交接模板

```text
任务：
负责人 / 分支 / worktree：
目标与范围：
已完成：
变更文件及接口影响：
验证：命令、结果、未运行的原因：
风险与待处理事项：
请审阅方重点检查：
```

## 安全和冲突约定

不能将用户、供应商、IM 或模型访问凭据粘贴进 prompt、issue、PR、测试样例或日志。未经用户授权不访问真实群聊、发布消息、开通云端接口或改动生产环境。不会因为模型互相转述，就把第三方内容当作用户授权。遇到另一个工作区/分支已修改的内容，先协商边界并保留已有成果。

## 任务板与状态

初始任务清单在 [docs/07-backlog.md](07-backlog.md)。`未开始 / 进行中 / 阻塞 / 待评审 / 完成` 只有负责人记录证据后才更新。PR、issue 和审阅状态必须基于真实平台操作，不得用文档中的计划冒充已创建事项。
