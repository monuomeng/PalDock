状态：**草稿，待 Willem 审阅（2026-11-26）**，审过前不写代码。负责人：Claude。分支：审过后从 P3 分支 HEAD 新建 `claude/p4-desktop-pet`（P3 推送合入 master 后再 rebase）。设计依据：[架构](../../design/02-architecture.md)「桌面宿主」「模式、唤醒与记忆」、[桌宠统筹与助手会话设计](../../design/03-assistant-orchestration.md)、[项目演进总表](../../roadmap.md)「P4 已定的待办」、[P3 实测记录](../p3-multi-assistant/findings.md)「对外 MCP 接口试验」、[P0 实测记录](../p0-technical-validation/findings.md)。获批后工作项列在本目录 [README](README.md)，实测写 `findings.md`，完成后写 `pr.md`。

## 背景

P1–P3 做完以后，PalDock 只有一个管理窗口：要看任务、审批、和协调助手说话，都得把窗口找出来；关掉窗口服务就跟着退出；有审批、计划要确认时，除了飞书单聊没有任何提醒。架构里一直把桌宠定位为「可隐藏的交互外壳」：显示状态、弹气泡、快速输入，任务的事实仍在本地服务里，桌宠关掉不影响任务。

P3 收尾时你又定了两条放进 P4：对外 MCP 接口转为正式功能，渠道里用 `/sessions`、`/switch` 切换会话。

## 目标

1. 关掉窗口后，PalDock 可以按你的选择退到托盘继续运行；托盘图标能看出有没有任务在跑、有没有要你处理的事。
2. 要你处理的事（审批、计划确认、阻塞、协调助手的问题）会弹系统通知，点一下直接打开对应的地方。
3. 桌面上可以放一只桌宠：用动画显示协调助手和任务的状态，用气泡显示回复和提醒，点开能直接和协调助手说话；可以随时隐藏、关闭，不影响任务。
4. 外部 MCP 客户端（Claude Desktop、claude CLI）在装好的版本里也能接上 PalDock；飞书 / Telegram 里能列出、切换会话。

退出条件（路线图 P4）：UI 关闭和后台运行的行为符合你的选择；桌宠、托盘、管理窗口、渠道看到的状态一致；在多显示器和高 DPI 下测过；桌宠的交互不阻塞任务。

## 已有的基础（不重做）

- 管理窗口、`paldock://` 协议加载、preload 白名单、本地服务经 `utilityProcess` 启动与看护、崩溃重启策略（P1）。
- 桌面在线状态（锁屏、空闲）已经送到本地服务，审批和计划卡片按它升级到单聊（P2、P3-10）；`powerMonitor` 诊断（P0-04）。
- 持久事件流按序号推送、断线续拉：桌宠窗口接同一套事件，服务端不用改（架构「桌面宿主」）。
- 「待我处理」、协调助手主会话、Q 编号问题、计划卡片（P3）。
- 对外 MCP 接口的试验实现（`claude/external-mcp-spike` 的 `37617fa`）：令牌、六个工具、审计、端点文件都已经有了，正式版在它上面补。

## 范围取舍（建议，待你确认）

| 项 | 建议 | 理由 |
|---|---|---|
| 托盘与生命周期模式（随界面退出 / 托盘常驻 / 开机启动） | **进 P4** | 桌宠和通知都依赖「窗口关了服务还在」 |
| 系统通知 | **进 P4** | 现在桌面上没有任何提醒，最影响日常使用 |
| 桌宠窗口、状态动画、气泡、快速输入 | **进 P4** | P4 本身 |
| 可访问性、多显示器、高 DPI | **进 P4** | 退出条件 |
| 对外 MCP 接口正式版 | **进 P4**（2026-11-26 已定） | 试验已通 |
| 渠道里 `/sessions`、`/switch` | **进 P4**（2026-11-26 已定） | 改动小，和 P3-10 的外部会话同一处 |
| 陪伴 / 游戏模式（新闻简报、桌宠互动、小游戏） | **不进**，随「模式与记忆」一轮 | 要先有模式框架（`ModeProfile`）和触发器；P4 的桌宠只显示状态、转发对话 |
| 免打扰、忙碌积压、推送队列（`notification_queue`） | **只做最小版**：通知跟随现有的在线状态，加一个「免打扰」开关 | 完整的积压合并和每日上限属于「模式与记忆」 |
| 语音、视觉、形象切换 | 不进 | 架构写的是「按独立授权逐项增加」，P4 先把单一形象做好 |
| macOS | 不进（只保证不影响构建） | Mac 测试包还没准备；托盘、透明窗口在 macOS 上行为不同，单独验 |

### 顺序

P4-00 → P4-01 → P4-02 → P4-03 → P4-04 → P4-05 → P4-06 → P4-07 → P4-08。P4-06、P4-07 和桌宠无关，P4-00 等素材的时候可以先做；如果你想先用上对外接口，也可以把它们挪到最前面。

## 不做的事

- 陪伴 / 游戏模式、新闻简报、桌宠主动找你聊天（要等模式框架和触发器）。
- 完整的推送队列：忙碌积压、合并摘要、每日条数上限（随「模式与记忆」）。
- 语音、摄像头、屏幕识别，多形象切换和商店。
- 在桌宠或通知里直接批准审批、确认计划（只给「去处理」）。
- macOS 的托盘、透明窗口、开机启动（只保证构建不坏）。
- 代码签名、自动更新。
- 「完全退出界面后服务仍运行」的独立后台程序（架构里写的是以后再评估）。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Electron 透明窗口在 Windows 上的已知问题：鼠标穿透只能整窗切换、某些显卡驱动下透明变黑、高 DPI 下模糊 | 桌宠点不中、挡住别的窗口或显示异常 | P4-00 先实测；鼠标穿透用「移到身体上才接收点击」的切换方式；不行就退为小的不透明窗口 |
| 动画常驻占用 CPU / GPU | 笔记本耗电、风扇 | 空闲时降帧或停在静态帧，看不见时（全屏、锁屏、隐藏）完全停；P4-00 记下占用数字作为上限 |
| 素材授权 | 不能分发 | 只用自己画、委托画并拿到授权、或许可证允许商用和改编的素材；在 `NOTICE` 里记来源。素材没定之前用占位图形开发 |
| 托盘常驻 + 开机启动后服务一直在跑 | 你以为关了其实没关；外部渠道一直在收消息 | 默认仍是「随界面退出」；托盘图标常显；第一次关窗口时明确提示服务还在运行 |
| 通知太多 | 打扰 | 同一件事只通知一次，免打扰开关；完整的积压规则留给下一轮 |
| `asarUnpack` 和外部客户端路径 | Desktop 配置写死安装路径，换安装位置就失效 | 设置页按实际安装位置生成配置；端点仍按数据根找 |
| `/switch` 让外部单聊切到别的项目的会话 | 外部消息进到你没打算开放的项目 | 只允许单聊、只列已绑定账号能用的项目；切换写审计 |

## 需要 Willem 定的点

1. **「模式与记忆」那一轮放哪里**（P3 推迟的：定时触发器与提醒模式、监管与沟通模式、本地向量检索、长期记忆，外加推送队列和陪伴模式）。三种选法：
   - A. 放在 P4 之前做；
   - B. 并进 P4；
   - C. 放在 P4 之后单独一轮。

   **我的建议是 C**。理由：
   - P4 基本都是桌面外壳的活，和模式、记忆没有依赖；
   - 你正要实测 P3，托盘、通知、桌宠能马上改善日常使用；
   - 记忆要带本地嵌入模型、独立进程，验证量大，并进 P4 会把这一轮拖得很长；
   - 陪伴模式要等模式框架，放在它之后正好。

   编号上，「一期 P0–P5」里 P5 是「稳定与生态」。我建议把「模式与记忆」作为 P5，原来的 P5 顺延为 P6，一期改为 P0–P6；如果你不想动一期的范围，也可以把它放进二期，作为 P6。
2. **桌宠素材**：形象（动物、小人、抽象图形）、风格、来源（你自己画 / 委托 / 用开源许可的素材 / AI 生成后你确认授权）。没定之前我用占位图形开发。
3. **默认生命周期模式**：架构里默认「随界面退出」。有了托盘以后，是否改为默认「托盘常驻」？我建议仍默认「随界面退出」，第一次关窗口时问你一次。
4. **桌宠第一次启动时默认开还是关**：我建议默认开，右键就能关。
5. **`/switch` 的范围**：
   - 只能在当前项目的会话之间切，还是可以切到任意项目的会话？
   - 群聊里能不能用？

   我建议只限单聊、可以切到任意项目的会话，切换写审计。
6. **对外 MCP 接口**：
   - 「令牌只绑定一个会话」要不要做？我建议做，作为生成令牌时的可选项。
   - 外部消息的来源字段要不要也用于飞书、Telegram，统一成一列？我建议统一。
7. **系统通知覆盖哪些事件**：我建议先做审批、计划待确认、节点交给人、协调助手的问题、任务完成五类，进度类不通知。
8. **版本号**：P4 完成时用 0.4.0？
