离线测试和本机真实执行器的自动实测（[findings.md](findings.md) 的 P3-11 小节）都过了以后，下面这些需要你本人在装好的新版上走一遍。每项后面写「通过 / 不通过 + 现象」，发回给我。

## 1. 桌面对话与计划

1. 「对话」页选你的项目（没有项目时点「选择项目目录…」）。
2. 说一句：「给 README 加一行说明，再补一个检查 README 存在的测试」。
   - 预期：协调助手回复，提出一个两节点计划（开发 → 测试）。
   - 计划卡片直接出现在对话里，可以在卡片上确认或退回；简单计划（只有一个步骤、不带检查命令）会显示「将自动确认」，30 秒内可以点「撤回自动确认」，不撤回就自动开始，「自动处理记录」里多一条「计划自动确认」。「设置 → 自动处理」里可以按项目关掉。
3. 打开任务详情（对话卡片上「在任务页修改」），看计划卡片：
   - 每个节点显示角色、执行器、依赖、检查命令；
   - 改一个节点的执行器，再改回来；
   - 写一句意见后确认。
   - 预期：节点按依赖开始，开发节点做完后由审阅助手审，然后合进集成分支；全部通过后显示「待合并」和分支名。
   - 审批：助手改自己 worktree 里的文件、跑 `node --test` 这类普通命令**不会**来问你（宿主直接批准并记审计）；装依赖、git push、联网下载、写 worktree 外的文件仍会来要审批。
4. 「自动处理记录」页能看到审阅助手放行的记录。
5. 用 git 把集成分支合进你自己的分支（PalDock 不会替你合），确认内容正确。

## 1b. 项目页与单人模式（0.3.4）

1. 打开「项目」页，选你的项目：能看到工作模式、角色表（启用、执行器、隔离方式、审批、跳过审阅、检查结果）、简单计划自动确认、准备命令、远程审批等级。「设置」页里不再有这些按项目的项。
2. 关掉「测试助手」，在对话里让协调助手提一个要用测试助手的计划：预期它被拒（协调助手会换角色或告诉你要启用）。
3. 工作模式切到「单人」（会弹确认：直接在项目目录里改）。在对话里说一个小改动，例如「README 加一行」：预期助手直接改项目目录里的文件、不拆计划；`git status` 能看到改动，没有提交。勾上「改完让审阅助手看一遍」再试一次：对话里多一条「审阅助手：…」。
4. 切回「团队」，把开发助手的隔离方式改成「直接在项目目录里改」（会弹确认），提一个两个开发节点的计划：两个节点依次在项目目录里改（不会同时改），任务完成后改动在你的工作区里、没有集成分支合并。
5. 把开发助手的审批改成「每条都审批」：开发助手每改一个文件都会来问你；改成「只审批高风险」：装依赖不再问，写工作目录外的文件仍会问。

## 1c. 默认在当前仓库协作（0.3.6）

已有项目保持原来的 worktree 方式；新登记的项目默认「当前工作区」。可以在「项目」页把一个测试项目切到「当前工作区」。

1. 在一个功能分支上，先自己暂存一点改动（`git add` 一个文件）。在对话里让协调助手提一个「开发 → 测试」的计划并确认。预期：IDE 里马上能看到开发助手的改动；测试助手验证的是这些还没提交的改动；你暂存的内容不变；做完任务显示「改动在你的工作区里，还没提交」。
2. 对协调助手说「只提交这次修改」：对话里出现提交卡片，逐块列出改动，助手写的默认勾选、你的不勾；你暂存过的文件有提示。确认后看 `git log -1 --stat`（只含勾选的）和 `git diff --cached`（你原来暂存的还在）。
3. 说「推送当前分支」：推送卡片写明远端、远端分支和要推的提交，确认后推送（建议先用一个测试仓库的远端试）。
4. 助手干活时你在 IDE 里切一下分支：预期很快暂停，正在跑的执行中断，「项目」页和对话里提示原因和变动的文件，可以选「在新分支上继续」或「取消」。
5. 助手自己想运行 `git commit` / `git push` 时被拒绝（任务详情的执行记录里有说明）。

## 1d. 只提交这次、只推送看过的、暂存区、审批分层（0.3.7）

建议先在一个测试仓库里试（带一个临时远端：`git init --bare` 一个目录，`git remote add origin <目录>`）。

1. 开两个对话（对话页「新对话」）。在对话 1 里让协调助手提一个改某个文件**上半部分**的计划，在对话 2 里提一个改**同一个文件下半部分**的计划，都确认、做完、不提交。
2. 在对话 2 里说「只提交这次修改」。预期：卡片写着「范围：这个对话发起的任务」，只列下半部分那一块，默认勾选；确认后 `git show HEAD` 只有下半部分，上半部分还在工作区里。
3. 在对话 1 里再说「只提交这次修改」：预期上半部分那一块还在卡片上、默认勾选。
4. 在 IDE 里，趁助手干活时手动改同一个文件的另一处。预期：你改的那块出现在卡片上但**不勾**（说明是「这次任务期间发生、但核对不上助手的写入」）；助手做完之后你再改的，不出现在卡片上。
5. 说「推送当前分支」，卡片出来后先别确认：在另一份克隆里往同一个远端分支推一个提交，再回来点确认。预期：卡片作废，说明远端变了，没有推送。重新让助手提出后再确认，推的是卡片上写的那个提交。卡片列出的是实际推送地址（配了 `pushurl` 时是它）和提交总数。
6. 暂存区：助手干活时你在终端里 `git add` 一个文件。预期：这一轮结束后项目暂停，对话里出现暂存区卡片；点「保留现在的暂存区」继续，或点「恢复到这一轮开始前」只改暂存区、文件内容不动。弹卡后你又暂存了别的文件再点恢复，卡片作废、不覆盖你的操作。
7. 项目外读文件：让测试助手读项目外的一张图片。预期：它这一轮自己生成的文件（比如截图）直接放行，不出审批；项目外原来就有的文件先交协调助手判断（审批上写着「协调助手正在判断」），它拿不准或 90 秒没答复才轮到你；读 `~/.ssh`、`.env` 之类敏感路径时只能你批，「允许一次」按钮可以点；同一次执行一下子来好几个审批时，「待我处理」里合成一张卡，可以「全部允许一次」或逐项处理。

## 2. 飞书（或 Telegram）

前提：飞书渠道已启用、你的单聊已绑定，项目的远程审批等级用默认的 L1。

1. **普通消息**：在单聊里发「README 里加一行作者信息」。
   - 预期：回「收到，已交给协调助手」，随后收到协调助手的回复。
   - 桌面「对话」页出现「飞书 · 你的名字」会话，你的消息标着「来自飞书」。
   - 不应该再出现「新建任务？」卡片。
2. **计划卡片**：让桌面空闲（锁屏或 5 分钟不动），等协调助手提出计划。
   - 预期：单聊收到「计划待确认」卡片。
   - 计划不带检查命令：点「确认」后开始执行，桌面计划显示「在飞书上确认」。
   - 计划带检查命令（L1）：卡片没有确认按钮，提示回电脑确认。
3. **编号问题**：在对话里让协调助手「有不确定的地方就问我」，锁屏等它发问题卡片（标题带 Q 编号）。分三次回答：
   - **引用回复**：长按问题卡片选「回复」再写答案。预期回「已把你的回复交给协调助手（Q…）」，桌面上这个问题标为「已答」。
   - **带编号**：直接发「Q12 用 cookie」（编号换成卡片上的）。
   - **只剩一个待答问题**：直接回一句话。
4. **拿不准**：同时有两个没答的问题时，回一句不带编号、也不引用的话。
   - 预期：不会算成任何一个问题的答复，协调助手会问你是在回答哪个。
5. **命令照旧**：`/tasks`、`/new 给 README 加一行`、`/continue` 都和 P2 一样。
6. **完成汇总**：第 1 步发起的任务做完后，单聊里收到协调助手的汇总。

## 3. 重启与睡眠（P2 遗留 + P3-09）

1. **执行中退出**：任务执行中直接关掉 PalDock，再打开。
   - 预期：「待我处理」顶部显示「本次启动自动恢复了 N 项」，节点继续，或补记结果、交给你处理。
   - 任务管理器里不应残留旧的 codex / claude 进程。
2. **睡眠唤醒**（P2-09 遗留，P3-11 自动实测没覆盖）：有任务在执行时让电脑睡眠 5 分钟以上，唤醒后看：
   - 飞书长连接自动恢复（设置页渠道状态回到「已连接」）；
   - 执行中的任务继续，或进入待确认 / 中断并给出恢复按钮，不会卡在「执行中」不动；
   - 睡眠前没处理的审批，唤醒后还能升级到单聊。
3. **Telegram**：如果你还在用，重复第 2 节的第 1、3 步。
