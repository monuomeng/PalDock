# 配置飞书自建应用

P2 的飞书渠道（积压 P2-08）用你自己租户里的一个**企业自建应用**，经长连接收消息，不需要公网地址。P0 用过的测试应用可以直接沿用，只需补下面第 2、3 步里新增的权限和回调。**App Secret 相当于密码，不要发到聊天、文档或仓库里**，只填进 PalDock 的设置页。

## 1. 创建应用（已有 P0 测试应用可跳过）

1. 打开[飞书开放平台](https://open.feishu.cn/app) →「创建企业自建应用」，名称例如 `PalDock`。
2. 「添加应用能力」→ 添加 **机器人**。
3. 「凭证与基础信息」里能看到 **App ID**（`cli_` 开头）和 **App Secret**，第 4 步要用。

## 2. 权限（「权限管理」里搜索并开通）

| 权限 | 用途 |
|---|---|
| `im:message.p2p_msg:readonly` 读取用户发给机器人的单聊消息 | 单聊收消息 |
| `im:message.group_at_msg:readonly` 接收群聊中 @机器人消息事件 | 白名单群里 @机器人 |
| `im:message:send_as_bot` 以应用的身份发消息 | 发卡片、更新卡片 |
| `contact:user.base:readonly` 获取用户基本信息 | 配对和桌面列表里显示对方名字；不开也能用，名字会显示成 `飞书用户 …末 6 位` |

**不要**开通「获取群组中所有消息」：PalDock 在群里只处理 @机器人 的消息。

## 3. 事件与回调（都选「长连接」）

长连接的订阅方式要求保存时已有程序在线：先完成第 4 步、在 PalDock 里启用飞书并看到「已连接」，再回来保存这里的设置。

1. 「事件与回调 → 事件配置」：订阅方式选 **使用长连接接收事件**，添加事件 **接收消息 v2.0**（`im.message.receive_v1`）。
2. 「事件与回调 → 回调配置」：订阅方式同样选 **使用长连接接收回调**，添加回调 **卡片回传交互**（`card.action.trigger`）。没有这一步，卡片上的按钮点了没反应。
3. 「版本管理与发布」→ 创建版本 → 可用范围选你自己（或测试成员）→ 发布。权限和事件改动都要发布新版本后才生效。

## 4. 把凭据交给 PalDock

打开 PalDock →「设置 → 外部渠道 → 飞书」，填 App ID 和 App Secret，勾选「启用」，保存。凭据写进系统凭据库（Windows 凭据管理器 / macOS 钥匙串），界面之后只显示 App ID。

也可以在 Windows 命令行里提前写入（`/pass` 后不带值，回车后输入 Secret，不会留在命令历史里）：

```bat
cmdkey /generic:paldock/feishu /user:<App ID> /pass
```

## 5. 配对与使用

1. 在飞书里搜索应用名，打开和机器人的单聊，发任意一句话。
2. 机器人回一张卡片，上面有 8 位配对码；PalDock「设置 → 待确认的配对」里出现同一个码。核对一致后点「确认绑定」。
3. 之后在单聊里：发 `/help` 看命令；直接发一句话会生成「新建任务」确认卡，点确认才建任务；任务进度、待验收、需要远程审批的操作都会以卡片发到这个单聊。
4. 群聊：把机器人拉进群并 @它 说一句话，这个群会出现在「设置 → 群聊白名单」，勾选后群里 @机器人 才会被处理，且发起人必须是已绑定的账号。审批和验收按钮只发到单聊。

## 常见问题

- **状态一直「连接中」或报凭据错误**：核对 App ID / Secret；应用是否已发布版本。
- **断线恢复后消息晚到约 5 分钟**：飞书平台的补投行为（P0 实测约 314 秒），设置页会提示「渠道刚恢复」；重复投递会按事件 ID 去重。
- **想停用**：设置页取消「启用」并保存；停用期间积压的待发消息会标记为失败，不会在重新启用时补发。
