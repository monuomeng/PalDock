# 阶段目标与迭代路线

阶段顺序是建议，不代表承诺日期。每阶段完成后由负责人提供验证记录；未通过退出条件不能把阶段标为完成。

| 阶段 | 目标 | 交付 | 可验收退出条件 |
|---|---|---|---|
| P0 方案与技术验证 | 验证 Windows、Codex 会话、审批、存储及飞书可行性 | 最小独立实验、接口记录、风险与 ADR | 确认发现/启动/流式/取消/审批/恢复能力；本机迁移重启实验；飞书长连接权限及去重方案形成记录。不可用能力明确标注 |
| P1 本地最小产品 | 桌面 + 本地任务 + Codex | 可安装的开发预览，任务和会话列表、审批、日志 | 在选定的临时测试仓库从创建任务到执行及回显跑通；拒绝/取消/崩溃重启/重复启动测试通过；明确备份与卸载 |
| P2 外部渠道 | 飞书单聊与授权群聊 | 渠道适配器、身份映射、消息回传 | 测试租户完成消息接收、身份/群白名单、会话路由、去重、断线重连、审批关联；拒绝未授权来源 |
| P3 多助手协作 | Codex + Claude 开发/测试/文档分工 | 协调器、依赖图、独立会话、工作区隔离 | 至少两执行器完成开发→测试→汇总；依赖失败、审批超时、取消、冲突与重启恢复验证；实际可用性以安装和账户权限为准 |
| P4 桌宠体验 | 桌宠动画、对话气泡、托盘、可访问性 | 可关闭或隐藏的 UI、桌面提示 | UI 关闭和后台设置行为符合用户选择；状态一致；桌面多显示器和高 DPI 测试；交互不阻塞任务 |
| P5 稳定与生态 | 更多渠道、模型、任务模板与扩展 | 发布、诊断、备份、兼容矩阵 | 干净安装/升级/卸载、备份恢复、兼容与授权审查完成；渠道、插件可控关闭 |

## 模块迭代

- **桌面**：P1 管理窗口优先；P4 透明桌宠、形象切换和语音。语音和视觉能力按独立授权逐项增加。
- **协作**：P1 单协调者+单执行者；P3 子任务依赖、并行与人工审核；以后增加复杂编排、预算和团队策略。
- **会话**：P1 本地与运行时映射；P2 外部身份和渠道线程；后续跨渠道显式绑定及导出。
- **执行器**：P0 Codex 能力探测；P3 Claude；后续其他 CLI/SDK。可观测探针作为可选插件研究，不负责绕开权限。
- **渠道**：P2 飞书和 Telegram（首版仅此两个外部渠道）；钉钉等以后酌情逐一适配和测试。WebSocket、Webhook、附件及审批按平台能力分别实现。
- **数据与安全**：P1 SQLite、迁移、权限和审计；后续细粒度身份、资源预算、加密备份及扩展审核。
- **模型网关**：先实现可替换模型接口；Higress 在协议、凭据、模型和流式分别验证通过后作为可选能力。

## 发布门槛

每阶段至少提供可复现构建说明、版本/兼容记录、关键用户路径测试、恢复及拒绝测试、变更记录、已知限制。无真实 API Key 时使用 mock；实时外部集成测试明确标记为 opt-in 并控制成本。
