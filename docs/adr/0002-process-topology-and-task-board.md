# ADR 0002：进程拓扑、任务板编排与多平台边界

状态：已接受（设计层面），2026-11-20。细化并部分替代 [ADR 0001](0001-initial-architecture.md) 中的未决项；具体参数仍待 P0 实测，实验失败时提出替代 ADR。详细设计见 [架构与模块边界](../design/02-architecture.md)。

## 背景

ADR 0001 定下了本地优先、契约驱动的方向，但没有回答：本地服务以什么进程形态运行、助手之间如何协作、审批如何在桌面和外部渠道之间分配、数据如何保存和保留、首批支持哪些平台和渠道。2026-11-20 的架构草案 v0.2 和对 Coopanion、AionUi、Happier、OpenClaw、Orkas 的源码浅读给出了这些问题的答案，用户在当天逐项确认。

## 决策

1. **进程拓扑**：采用 Electron。本地服务作为 Electron 子进程运行（`utilityProcess.fork`，备选 `child_process.fork` + `ELECTRON_RUN_AS_NODE`），与界面通过本机 IPC（Windows 命名管道 / macOS Unix 域套接字）加一次性令牌通信，不开 TCP 端口。固定 3 秒重启，5 分钟内崩溃超过 5 次停止；数据根放 PID 锁文件。以后如需「界面完全退出仍运行」，再评估独立后台程序。
2. **多平台**：Windows 和 macOS 都是主机，共用一套代码，操作系统相关能力（IPC、凭据、自启、电源、进程树、签名分发）放在 `packages/platform` 接口后。iOS 只做远程客户端（查看、对话、审批、通知），不运行本地服务和执行器；原生 iOS 客户端及其中继方案另起 ADR，在此之前手机端通过飞书/Telegram 使用。
3. **任务板编排**：协调助手提出计划，确定性调度器推进任务图，专业助手之间不互发消息。子任务交付后只能进入 `review`，由验收闸门重跑验证命令后推进。编排工具通过每次 Run 注入的本机 MCP 桥提供，身份由令牌和 Run ID 确定。
4. **角色与执行器分离**：每个角色的执行器由用户选择，出厂默认值可改，唯一硬约束是能力检查。协调助手负责项目总览，不额外限制能力，但受项目授权、审批和审计约束。审阅与开发同一执行器时只提醒，审阅必须用独立会话。
5. **自动处理与上限**：简单任务可跳过确认或审阅，所有跳过和自动批准写入 `auto_decisions` 记录单；退回重做次数不设上限，只记录；并发（10 / 4 / 同会话串行）、自动推进护栏（20 次 / 2 分钟 / 30 分钟）和单次唤醒软硬上限（20 / 40）强制执行，均可配置。
6. **审批路由**：桌面优先；桌面 3 分钟无操作、锁屏/空闲或 UI 未运行时升级到绑定的外部单聊，先到者为准。按项目设置远程审批等级 L0 仅桌面 / L1 低中风险（默认）/ L2 含高风险（显式开启），等级只能在桌面修改；风险由策略引擎判定。
7. **渠道**：首版外部渠道只有飞书和 Telegram（P2），P1 只有桌面和模拟渠道。入站先落库再处理，墓碑去重，会话串行；出站经 outbox。
8. **存储**：用户选定数据根，SQLite WAL 单写者；状态表为准，事件同事务追加，持久事件与临时事件分离。数据库不加密，凭据在系统凭据库。保留期：正文、摘要、长期记忆不自动删除；工具结果和终端输出 7 天；渠道附件和未引用产物 30 天；日志 14 天。worktree 默认放在数据根，可按项目改到项目旁边。
9. **模式、唤醒与记忆**：ModeProfile 定义模式（P1 项目协作和任务提醒）；唤醒循环加触发器驱动模型；记忆分原始记录、会话摘要、长期记忆、向量四层，P1 只做 FTS5（trigram），P2 加 sqlite-vec 和本地 bge-small-zh-v1.5。原生压缩只在单次 Run 内使用。主动推送按用户状态积压，审批和阻塞不积压。
10. **ACP** 并入 P0-07 评估，与 Codex app-server、Claude Agent SDK 对比。
11. **待我处理**：P1 管理窗口首页集中显示需要用户行动的审批、阻塞和待验收，从业务状态派生，只单独存已读状态；已读、已审批、已验收互相独立。每次 Run 保留证据，反馈绑定到具体 Run。执行器断线而服务仍在时，Run 进入「执行状态待确认」，查实后再更新。桌宠（P4）、iOS 和渠道卡片读同一份数据。

## 理由

- 独立于界面的服务进程让桌宠或窗口崩溃不影响任务；放在 Electron 子进程里不必另带 Node 运行时，安装和看护都更简单。
- 本机 IPC 比本机 HTTP 端口少一类攻击面，不需要 Host/Origin 校验。
- 任务板让每次交接可审计、可恢复，避免助手自由对话造成的循环和双层分派；参考项目中有任务板的两个（AionUi、Orkas）也不让助手自由互发消息。
- 桌面优先的审批保证高风险操作默认在用户眼前决定，同时用户离开电脑时任务不必停摆。
- 平台层把 Windows 专属的东西隔离开，macOS 只需换实现；iOS 受系统限制不能做主机，做客户端最现实。

## 代价与风险

- 服务和界面同属一个 Electron 应用，用户完全退出应用后服务也停止。
- 多平台增加 CI、签名和公证成本；macOS 的文件夹授权弹窗和登录项行为需要实测。
- iOS 原生客户端需要中继，会引入新的信任边界和运维成本。
- 数据库不加密，依赖操作系统账户保护；正文默认不删，数据会持续增长（估计为每年几十 MB 级，未实测）。
- 各项默认值来自参考项目，未在 PalDock 上验证。

## 待确认
